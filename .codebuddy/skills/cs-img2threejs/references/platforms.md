# Host and Workspace Adaptation

The pack name is `cs-img2threejs`; requests using the original name `img2threejs`
select the same skill. It supports explicit invocation and task-driven loading by
`cs-cocos-specialist`. It does not select a model or activate a team workflow.

| Host | Project installation | Invocation/tool mapping |
|---|---|---|
| CodeBuddy | `.codebuddy/skills/cs-img2threejs/SKILL.md` | `/cs-img2threejs` or load the skill; use available file, shell, image and browser tools |
| Codex | `.agents/skills/cs-img2threejs/SKILL.md` | `$cs-img2threejs` or normal skill selection; user installs live under `~/.codex/skills/` |
| Gemini CLI | `.gemini/skills/cs-img2threejs/SKILL.md` | `/cs-img2threejs` command or skill selection; use the host's available shell/image/browser tools |

Claude adapters are generated by the pack's existing builder as well. The installed
host or caller supplies the resolved skill path and agent paths. Do not assume a
particular MCP server, browser API, nested-agent facility, or global symlink exists.
The host owns Blender dispatch, resolving any plugin-qualified persona name.

Set the working directory to the assigned asset workspace. Before the first run,
copy the installed skill directory to `.img2threejs/toolkit/` inside that workspace
using the host's filesystem tools. Require the destination to be absent; do not merge
over an existing run. This is a task-local runtime copy, not another registered skill.
Keep its `PROVENANCE.json` with the task. On resume, reuse the same copy and state;
switching source revisions requires a new task-local copy and revalidation.

This staging step is needed because `new_pre_spec_assessment.py` computes its corpus
and writable BM25 cache from its own `PROJECT_ROOT`, not the working directory.
Set `img2SkillRoot`/`img2_skill_root` below to the **staged** directory. On Windows:

```powershell
$img2SkillRoot = 'C:\path\to\asset-workspace\.img2threejs\toolkit'
python -B "$img2SkillRoot\forge\next.py" --state .img2threejs/state.json object-sculpt-spec.json
```

On POSIX:

```sh
img2_skill_root='/path/to/asset-workspace/.img2threejs/toolkit'
python3 -B "$img2_skill_root/forge/next.py" --state .img2threejs/state.json object-sculpt-spec.json
```

The upstream workflow's `forge/...`, `grimoire/...`, `docs/...`, `assets/...` and
`scripts/...` references are rooted at that copy of the skill. Its relative output
paths belong to the current asset workspace. Commands printed as `python3 forge/...`
need the same installed-root expansion. Use `--help` on that installed script before
adapting flags. Use UTF-8 for JSON/text; retain quotes around paths with spaces.

`runtime/...` paths in upstream references refer to the separate showcase/project
runtime; that directory is not shipped here. Point `IMG2THREEJS_SHOWCASE_ROOT` at an
existing compatible showcase when using those helpers/tests, or implement capture
and export in the assigned project's preview. Identify a missing runtime explicitly.
Do not silently fetch a showcase, optional model/plugin or external asset.

Keep the installed skill reusable across projects. Staged cache files are task
artifacts; do not copy them back to the installation. Use `-B` or the interpreter's
`PYTHONDONTWRITEBYTECODE=1` setting to avoid unnecessary Python bytecode files.
