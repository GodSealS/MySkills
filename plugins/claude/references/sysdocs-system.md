# SysDocs 体系约定（sysdocs-system）

本协议集中定义 schema 2、内容归属、双布局读取、影响范围和迁移。生成/维护技能、开发接入方和 validator 共用此契约。文档解释事实；知识库提供检索候选；规范和决策保存意图，彼此不代行批准。

## 1. 目录与权威范围

```text
SysDocs/
├── README.md                    # 用途、术语、阅读路线和导航
├── PROJECT-MAP.md               # 当前架构、模块执行流程、模块关系、项目工作流四图总览
├── architecture/
│   ├── overview.md              # 边界、部署单元、模块协作
│   ├── modules/<module-id>.md   # 职责、内部组成、关键入口
│   └── flows/<flow-id>.md       # 跨模块流程与异常路径，按需
├── files/
│   ├── README.md                # 整体源码范围、排除理由、索引导航
│   └── <module-id>.md           # 每个源码文件的唯一职责归属
├── specs/                       # 需求、契约、约束和验收，按需
├── decisions/                   # ADR 与替代关系，按需
├── VibeCoding/                  # 未实施设计及历史，不是当前架构
└── .meta/                       # 按需保存迁移和验证证据，不是正文
```

- project root 由用户指定，否则为当前 workspace 根；不向上或向下猜选项目。源码字段相对此根；Markdown 链接相对所在文档解析。解析路径必须仍在项目根内。symlink 默认不跟随；显式允许也须核对实际目标边界。
- monorepo 默认一套 SysDocs，记录 package/app 与部署边界；已有任务授权拆分时按指定 root 分开，否则不自行重排。
- architecture/files 描述核实的源码/配置及版本。specs 保存已接受且适用的预期要求，decisions 保存背景和历史取舍。源码与规范冲突先记录差异和变更依据，不能按现状自动改要求。
- 已有 `docs/adr/`、`spec/` 等权威资料保留原位置，SysDocs 建导航链接；每份资料只有一个权威正文。跨目录改写仍须属于任务授权。
- 按内容建立目录；空 flows/specs/decisions 不是合规要求。无源码项目可先写规范/方案，不虚构模块或已实现架构。

## 2. 三态清单与双布局读取

状态针对项目梳理完整性，不以目录存在判断；先识别布局再检查对应契约。

| 状态 | 旧 schema 1 布局 | 新 schema 2 布局 |
|---|---|---|
| `UNINITIALIZED` | 不存在、为空或没有系统梳理页面 | 同左；只有方案、规范、决策或 .meta 仍未初始化 |
| `PARTIAL-INITIALIZED` | 已有系统/模块页面但 SYSTEM_ROOT、manifest 或登记页不完整 | 已有概览/架构/文件页，但必需入口、对应关系、导航或元数据不完整；包括迁移中断 |
| `INITIALIZED` | SYSTEM_ROOT、modules manifest 与模块/拆分页双向一致 | README、PROJECT-MAP、architecture/overview、files/README 完整；有源码时模块和索引按 module_id 对应，声明范围有覆盖且导航可达 |

- 三态只是结构清单，不证明内容新鲜。未初始化由 init 显式完整梳理；部分状态由 update repair；完整状态按影响 update。
- schema 1 按原契约读取：SYSTEM_ROOT 的 modules[].id/path/pages/source_roots 对应 modules/ 的 module/page 与 module_id/page_id；保留原字段。允许原布局局部维护，不隐式改目录或升版本。新初始化和显式迁移只生成 schema 2。
- 布局版本约束事实页，不强制规范、决策和方案采用同一版本：旧库内新建的 specs/decisions/VibeCoding 页面按 schema 2 验证，既有 schema 1 方案仍可读取；新增这些页面不构成布局迁移。
- 双布局并存时，只有迁移记录和兼容跳转证明旧内容已转移才以新入口为准；未完成映射、两份活动正文或缺失目标为部分状态，先恢复/修复，不能任选一份覆盖。
- 仅含新位置链接的旧入口是兼容页，不强制补摘要、元数据或重复正文。未来未知 schema 只读并报告 FAILED，禁止降级、删除或重建来绕过 gate。
- 跳转豁免仅用于旧 SYSTEM_ROOT/modules 页面；新布局的 README、architecture 和 files 事实页仍需完整元数据与适用摘要，不能用跳转替代必需入口或源码范围声明。
- vibe 可在三态下仅创建前置方案，不补写当前架构冒充初始化。普通开发不因缺库强制 init；明确完整文档交付任务不能跳过完整性。

## 3. schema 2 最小元数据

```yaml
---
schema: 2
doc_type: architecture
updated: 2026-09-16
source_scope: committed
generated_from: <verified-commit-sha>
source_paths:
  - src/order/
---
```

| 字段 | 契约 |
|---|---|
| schema | 必填整数；新文档为 2，不靠修改数字完成迁移 |
| doc_type | overview / architecture / files / spec / decision / vibe |
| updated | 必填 ISO 日期或时间，不能冒充来源版本 |
| source_scope | 事实页 overview/architecture/files 必填：committed / committed+working-tree / unversioned |
| source_paths | 事实页必填，项目根相对文件或目录字符串列表，不用 glob；确无源码时为 [] |
| generated_from | committed 和 committed+working-tree 必填，可验证的基础提交；unversioned 省略并注明限制 |
| evidence | committed+working-tree 必填，项目根相对已有任务/评审证据文件路径，可带锚点；记录纳入文件与审查差异，文件存在不证明内容已复核 |
| module_id | architecture/modules 与 files 模块页必填，各自唯一且相互对应；overview/flow/files/README 不强制 |
| exclusions | files/README 可选的项目根相对排除路径或 glob 字符串列表；正文解释理由 |
| status | 可选 draft / active / stale / archived；active 需要范围内内容核实，不能仅凭格式通过 |
| owned_by | 有 human 块时为 mixed，其余可省略 |

spec/decision 不强制源码字段；历史 ADR 和外部权威资料不为格式改写。vibe 的 vibe_id、implementation、merge 见 [vibe 模板](sysdocs-vibe-template.md)。未知字段保留；schema 1 的 confidence/kb 等可保留作历史信息，schema 2 不重复强制。

specs/decisions 中未声明 schema 和 doc_type 的历史 frontmatter 保留原格式；声明了 SysDocs 字段的页面仍按对应契约检查，显式未知 schema 不享受历史格式豁免。历史格式豁免不跳过链接、人工块和脱敏检查。

不再维护 overview modules manifest：导航只链接实际模块页；整体覆盖范围只在 files/README 声明；完整文件职责只在 files 模块页维护。source_paths 是来源范围，不是第二份职责清单。移除 kb_bootstrap 重建触发语义；知识库后来可用只补充核实证据。

### 3.1 文件索引覆盖

files/README 的 source_paths 定义完整交付源码范围；exclusions 缩小该范围且须说明原因。模块文件索引使用固定表头：

```markdown
| 源码路径 | 职责 | 模块 |
|---|---|---|
| `src/order/service.ts` | 创建订单并协调库存预留 | `order` |
```

一行一个项目根相对文件路径、非空一句话职责、与本页 module_id 相同的模块。业务源码在声明范围内逐文件覆盖；每文件只有一个详细归属，其他模块链接引用。大型项目拆模块索引，不要求每文件一篇 Markdown。测试、配置和资源可按阅读价值单列或按目录说明，但不能借此漏掉业务源码。components/ 可能包含业务源码，不按名字整桶排除。无代码时 source_paths 为空，记录实际状态。

## 4. 头部检索摘要与写作

新生成的 overview/architecture/files 页在 frontmatter 后、详细正文前设置固定 `## 检索摘要`；可以先有 H1，不得在摘要前放其他正文。新 spec/decision/vibe 按内容适用性采用同样形式。

- 必须列关键入口或承担主要职责的类名/结构名，每项一句话职责；同名符号补模块或路径。不枚举全部内部类、方法或符号。
- 无类/结构时用实际函数、模块、配置项或流程为锚点；方案中的候选符号标为“拟议”，不编造名称。
- 补充重要跨模块关系以及事务、权限、数据归属、异常/补偿边界，避免只匹配符号而遗漏业务语义。
- 摘要随正文同步，只维护一份。工具先提取摘要和路径，筛选后再读取正文；不先将全文载入上下文再截断。大型库可按导航分批，但保留跨模块候选。
- 旧文档、历史 ADR、外部资料和兼容跳转缺摘要时回退正文或权威链接；缺摘要不意味着无关。历史报告保持原样。
- README 先讲用途和阅读顺序；模块页解释职责、协作和少量入口，完整文件清单留给 files。PROJECT-MAP 的四类总览图按下节要求提供，其他页面按阅读价值加图，不强制全类表、全方法签名或全量枚举。长页按实际主题拆分并链接导航。

事实引用用项目根相对路径及唯一可定位的具名符号，可沿用 `语言|路径:全限定名(签名)`；行号不是唯一标识。匿名回调用最近具名入口及上下文。数值写单位；流程写参与者、输入输出和异常；规范明确条件及强度，但不把现状自动提升为 MUST。

### 4.1 根目录项目图册

`SysDocs/PROJECT-MAP.md` 是 schema 2 的必需事实页，使用 `doc_type: architecture`、来源元数据及头部检索摘要。按 [项目图册模板](sysdocs-project-map-template.md) 集中提供当前项目架构图、模块执行流程图、模块关系图、项目工作流图。README 直接导航至此页；每类图链接相关模块/流程正文及可定位的源码或配置依据，详细说明继续保留在原权威页，不维护第二份模块或文件清单。

图只呈现已核实的当前实现；缺少源码、运行流程或项目自动化时，保留对应主题并明确“不适用/未实现/未核实”及证据或缺口，不画虚构节点。架构图表达系统和部署边界；执行流程表达触发、调用顺序及异常；关系图表达静态依赖、接口和数据归属；项目工作流表达实际开发、验证、构建、交付链路。不能用一张未区分语义的图代替四种视角。

新初始化、显式迁移和全量刷新必须交付图册；已有 schema 2 缺此页通过 update repair 补齐，不重建已有库。普通增量只核查受影响图及导航，不能因无关图册历史缺失强制全库修复。schema 1 继续原布局局部维护，不以新增图册为由隐式迁移。模块、接口、依赖、执行路径或工程工作流变化时，同步图册相应图及摘要；无影响时给出依据。

## 5. 知识库候选、风险与更新范围

接入遵循 cs-code-query：分别检查索引存在、实际接口可查询、覆盖范围和版本。默认优先已有可用索引，多后端可用时优先 CodeGraph；指定后端不可用则报告并回退源码，不静默换库。CodeGraph/Graphify 不调用 Understand-Anything 专属查询入口。普通查询不安装、不建库。

1. 从源码差异与行为/职责变化提取符号、调用方、依赖和业务词；知识库提供候选，不证明范围完整。
2. 检索全库摘要，以及模块名、旧名、业务词、路径和入口；缺摘要资料回退正文。知识库候选与文档候选取并集，不取交集。
3. 图谱有符号却无摘要匹配，核查摘要遗漏、文档缺失或无须说明；摘要有符号但图谱没有，核查改名、删除、拟议状态或索引缺口，不自动删文档。
4. 阅读候选正文，用源码/配置及适用规范验证结论。两路一致仍可能同时过时，必须检查来源和覆盖。无可用 KB 时以源码定位、引用搜索和业务语义补候选，记录降级及缺口；证据充分可完成，否则保留未验证项。
5. 模块拆分、职责迁移、事务/权限/数据归属/异常补偿/依赖方向变化时，额外阅读相关业务链路全部流程及约束，即使摘要未命中。不能可靠缩小范围时扩大到全部流程内容，包括模块页和外部权威资料；扩大阅读不等于全库改写。

在已有任务/PR 证据记录变更、语义影响、候选来源及差异、扩大阅读原因、更新页面/规范/决策和验证方法。无文档影响需具体理由，不创建空报告。入链、改名和删除也在范围内；必要范围不确定时不能宣称同步完成。

按影响与代码同变更交付文档。相关源码/文档再变更使受影响核实失效，需重验；范围外历史缺陷单列，不强制全库修复，本次必要约束/证据缺失须解决或明确未完成。初始化、显式全量刷新、迁移执行全量结构及覆盖检查。

## 6. 来源基线、工作区与人工内容

- 干净来源使用实际可验证的 generated_from。工作区来源使用 committed+working-tree，基础 SHA 只代表已提交部分；evidence 指向已有任务/评审证据，记录纳入路径和差异，涵盖暂存、未暂存以及纳入的新文件，不能只比较 HEAD。
- 同提交文档不预填未来 SHA；后续从 Git 变更历史恢复实际来源。检查后相关文件变化须重验，未受影响证据可复用。
- 无 Git、提交不可达或证据丢失时，按明确文件范围重新核实并注明无法精确恢复历史；不以 mtime 或自制指纹数据库替代来源。没有范围只能做结构检查，不能猜测内容已更新。
- 自动刷新只改事实说明。人工约束/理由保留原意，确认归属后迁往或链接规范/决策；不能分类则保留原文并报告。旧 human 块完整保留，成对且不嵌套：

```html
<!-- human:start -->
人工内容原文
<!-- human:end -->
```

- 已接受 ADR 保留历史正文；决策变化通过新 ADR 和替代链表达，可修定位链接/状态。源码已落实并核实后，只吸收 Vibe 的已实现部分，历史提案保留来源链接；docs-only-confirmed 只允许整理方案/目标规范，不证明实现。
- 写入前脱敏，不读取/复制秘密值；环境变量只记名称和用途。默认排除 .env*、凭据、密钥/证书、日志/dump、依赖缓存、构建和生成产物；例外应说明安全来源。疑似秘密阻断原值写盘，报告位置并使用 `[REDACTED:<类型>]`。

## 7. 显式迁移、恢复与生命周期

迁移仅由 cs-sysdocs-update 显式执行，不在普通查询/开发中自动重排。授权内可逆同步直接执行；超出任务的迁移、删除原文或改变业务约束才需要具体确认。

| 旧内容 | schema 2 归属 |
|---|---|
| SYSTEM_ROOT 概览/术语/导航 | README；系统关系进入 architecture/overview |
| modules 职责/组成 | architecture/modules，尽可能沿用 module_id |
| 详细文件职责 | files 模块页，整体范围进入 files/README |
| 跨模块流程 | 有独立阅读价值时进入 architecture/flows |
| MUST/契约/业务要求 | 核实依据后整理到或链接权威规范，不自动批准 |
| 设计理由/human 块 | 保留原文和来源，有依据才形成决策，不自动设 Accepted |
| VibeCoding/.meta 历史 | 原样保留真实状态与历史 schema，不冒称新验证证据 |

1. 盘点旧文件、模块 ID、未知字段、权威资料、人工块及入链，给旧→新映射；无法映射的保留旧文件并列待处理。
2. 核对授权与未提交改动，保留可恢复 Git 点或备份；仅有 HEAD 不能保护未提交内容。
3. 在项目内临时区域生成结果，记录映射、备份/暂存位置与阶段 prepared/applying/complete；复用 .meta 或已有任务记录，不新增调度平台/快照库。目标冲突先保全，不覆盖用户内容。
4. 比对正文、human 原文、未知字段、导航/入链、覆盖和必要约束，验证通过再按映射整体落地。多文件替换不假称文件系统原子事务，开始前写明恢复步骤。
5. 中断后凭同一记录核对已替换/未替换项及后来用户修改，再继续或恢复；不能安全区分时保留两边并报告。完成后标 complete，重复运行识别已完成映射，不再改写正文。

生命周期：draft 为未完成生成或提案；active 为声明范围结构及内容均核实；stale 为事实/引用过期；archived 为明确替代的历史。仅更新实际受影响状态，不因 KB 缺失降级已充分核实页面，不因 KB 后来可用重建边界。归档页保留链接和历史，不能静默删除。

## 8. 结构验证与内容核实

| 类型 | 检查 | 能证明什么 |
|---|---|---|
| 结构 | 元数据、摘要位置/格式、路径/链接、覆盖/唯一归属、迁移保全 | 声明范围符合结构契约 |
| 内容 | 摘要正文一致、符号职责、依赖/流程/约束、来源版本、候选差异与风险扩大 | 指定结论得到源码、行为测试或评审支持 |

复用 `scripts/validate-sysdocs.py <目标项目的SysDocs目录>`（从提供脚本的技能包位置调用；安装未携带脚本时报告缺口，使用可用等效检查并说明方法）。默认全库；`--files <项目根相对文档路径> ...` 检查受影响页及相关入链；仅因入链纳入的页面只检查相关链接，不把无关旧缺陷升级为本次阻断。`--summaries` 提取路径/摘要并列出缺摘要回退项，仅供筛选，报告 validation_kind: summary_extraction。validator 只读，不改源码、不执行迁移。旧 schema 1 保留兼容，新布局不按旧 manifest 规则判坏。

全量检查从已有事实页识别布局，入口缺失仍报不完整。局部模块检查包含对应架构页/文件索引是否配对；无关模块的历史不配对不阻断本次检查。读取失败若涉及指定页、其直接引用或必要模块/范围依赖则阻断；其余放入 `out_of_scope_issues`，并在 `unverified` 中声明无法检查这些页面的入链，不能当作已验证无影响。

报告明确 validation_kind: structure、content_verification: not_performed、scope、inventory、问题定位和 unverified。COMPLETE/PARTIAL/FAILED 均带范围；COMPLETE 只表示声明结构范围完成，不表示全库或内容同步完成。未具备完整符号/Mermaid 解析器时明确未验证项，不能把格式扫描当解析通过。局部检查不抹去范围外遗留项；初始化/迁移不能用局部通过冒充完整。

沿用规则族 FM（元数据/版本）、MAN（旧布局登记）、LINK（路径/链接）、HUMAN（配对/保全）、REF（引用）、MERMAID（实际能力内语法）、SEC（脱敏），补充 schema 2 摘要与覆盖/归属检查。阻断问题返回 FAILED，未覆盖项明确列出；历史 .meta/reports 原样保留。普通同步复用现有任务/PR 证据，不强制新增独立运行报告。记录 operation 时允许 init / repair / incremental / migrate / rebuild-boundaries / full-refresh / vibe，不能把迁移冒称普通增量。
