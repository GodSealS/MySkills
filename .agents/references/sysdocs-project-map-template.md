# 项目图册模板（sysdocs-project-map-template）

依据 [共享协议](sysdocs-system.md) 生成 `SysDocs/PROJECT-MAP.md`，README 直接链接此页。沿用 [概览模板](sysdocs-overview-template.md) 的来源字段，`doc_type` 为 `architecture`，不设 module_id。以下为写作形状，替换占位说明，按实际项目生成 Mermaid 图，不照搬示例系统。

```markdown
# 项目图册

## 检索摘要

- `<真实入口/核心模块>`：<一句话职责>。
- 关联边界：<运行、依赖、数据归属和工程交付链路；什么变化需更新本文>。

## 当前项目架构图

<Mermaid flowchart：用户/外部系统、应用/服务、模块层次、存储与部署边界；注明运行时通信方向。>
<链接 architecture/overview.md、相关模块页及源码/配置依据。>

## 模块执行流程图

<Mermaid sequenceDiagram 或 flowchart：关键入口、输入、参与模块、调用先后、输出与异常/补偿；多条关键路径可分图。>
<链接实际入口符号、相关模块及 architecture/flows 中的详细说明。>

## 模块关系图

<Mermaid flowchart：静态依赖方向、提供/消费的接口、消息或共享数据，标注依赖类型；说明箭头语义，区别于执行顺序。>
<链接模块正文与具名接口证据；如存在循环或共享状态，如实展示。>

## 项目工作流

<Mermaid flowchart：项目实际开发/修改入口 → 验证 → 构建/生成 → 发布/部署/交付；注明人工步骤、自动化入口与失败反馈。>
<链接已有脚本、CI 配置或维护文档。无 CI/部署时如实说明，展示已有工作流。>

## 来源与未核实项

<本次核实范围、版本、图中节点/边的证据和已知缺口；未来方案另链 specs/decisions/VibeCoding。>
```

每类图使用稳定模块名或已有 module_id，并给出图例。图附近列关键证据即可，不重复完整文件索引。不适用的主题说明原因；未核实关系不可画成确定事实。规范项目尚无实现时明确此状态并链接权威要求，不能将目标架构画成当前架构。

验证：四个主题齐备；适用主题包含实际图；节点、方向、接口、路径和工程步骤逐一有证据；README 和正文链接可达；图与模块/流程页在同一来源范围内一致；分别报告 Mermaid 解析/渲染检查与源码内容核实，未执行的检查明确列出。
